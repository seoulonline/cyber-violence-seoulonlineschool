# DB 스키마

사이트가 사용하는 Supabase 프로젝트는 **`quntum_physics_01` (`zvdozshnwtfwthuotynb`, 서울 리전)** 입니다.
아래 마이그레이션은 이미 해당 프로젝트에 적용되어 있습니다. 여기 보관하는 이유는
프로젝트를 새로 만들거나 복구해야 할 때 그대로 다시 실행하기 위해서입니다.

| 파일 | 내용 |
|---|---|
| `01_cv_tables.sql` | `cv_students`, `cv_votes` 테이블 · 좋아요 자동 집계 트리거 · RLS 잠금 |
| `02_cv_views_rpcs.sql` | 갤러리 공개 뷰 · 로그인/제출/좋아요 RPC 함수 · 권한 부여 |

접두사 `cv_`는 같은 프로젝트에 있는 물리 수업용 테이블(`reflections`,
`motionlab_submissions`)과 구분하기 위한 것입니다.

## 설계 요약

학생 개인정보(이름·학교·학년·반·번호)가 들어 있는 `cv_students` 테이블은
**익명 접근을 전면 차단**했습니다. 브라우저는 다음 두 경로로만 DB에 접근합니다.

- **읽기** → `cv_works_public` 뷰. 작품 이미지·설명·좋아요 수만 들어 있고 개인정보 컬럼은 아예 없습니다.
- **쓰기** → `cv_login_or_register`, `cv_submit_work`, `cv_like_work`, `cv_my_votes` 함수.

로그인하면 학생마다 `token`(UUID)이 발급되어 브라우저에 저장됩니다.
제출·좋아요는 이 토큰이 맞을 때만 처리되므로, `id`만 바꿔서 다른 학생의 작품을
덮어쓰거나 대신 좋아요를 누를 수 없습니다.

좋아요 수(`like_num`)는 `cv_votes`에 행이 생기거나 지워질 때
트리거가 자동으로 맞춥니다. 애플리케이션 코드가 직접 세지 않습니다.
